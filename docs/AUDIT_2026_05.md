# Teajia — Total Site Audit, May 2026

> Scope: everything. Admin (30+ views), storefront (40+ routes), worker API (~150 endpoints), MCP server (7 tools), cross-cutting infra. The lens: **two questions**.
>
> 1. **What can be done by voice/agent through MCP from a phone?** Everything else is desktop-form-fill. We want to flip that.
> 2. **For every action that *must* stay a form, does the flow flow?** Or does it ask too much, in the wrong order, in the wrong place?
>
> This doc is the inventory + the gap + the prioritized fix list. No code changes — review, then we implement in waves.

---

## 0. Executive summary

**Current MCP coverage: 7 tools, ~29% of phone-first actions.** Reads (`search_tea`, `get_tea`, `list_low_stock`, `find_customer`) are solid. Mutations (`add_stock`, `remove_stock`, `record_sale`) cover the most-used path — restocking and ringing up a sale. **Everything customer-side is unreachable** (you can find a customer by voice; you can't create or tag one). **Everything pricing-side is unreachable**. **Invoice lifecycle is half-built** — you can create an invoice, you can't void or amend one.

**Action-flow audit: most flows are OK. The exceptions cluster.** The top friction is in (a) admin modals stacking on mobile — bulk ops, image crop, CSV import all degrade below `lg`; (b) account-switch state wipes — half-drafted product gone when you context-switch; (c) two empty stubs (`/account/orders`, `/account/samples`) that link from real pages and dead-end; (d) password reset has no entry point on `/signin`; (e) saved-stories and reading-history surface IDs instead of titles.

**Top security/infra gap (HIGH):** 31 client-side bundle gates with no server-side `requireBundle()` enforcement on most RPC handlers. Documented in `STATE_OF_THE_SITE.md #2` and unfixed. This is Body A foundation work — needs doing before more MCP surface is exposed, because every new MCP scope inherits the same enforcement trust model.

**Recommendation:** Three waves.

| Wave | Theme | Outcome |
|---|---|---|
| **1 — MCP Phase 2** | Customer + invoice lifecycle + pricing | Phone covers 70% of daily ops |
| **2 — Flow surgery** | Stub cleanup, modal nesting, account-switch drafts, /signin reset link | Forms that stay get faster |
| **3 — MCP Phase 3 + scope tiering** | Sourcing, tags, settings, threshold, owner-only scopes | Adrian can run a remote launch from a phone |

Detail follows.

# Part I — MCP Coverage Gap & Phone-First Plan

## I.1 What MCP currently does

Source: `worker/src/mcp.ts` (1,415 lines), `worker/migrations/066_mcp_tokens.sql`, `src/admin/views/MCPTokensView.tsx`.

**Scopes (4):** `inventory:read`, `stock:write`, `customers:read`, `sales:write`. All tokens default to all four — no per-token scope grants yet.

**Tools (7):**

| Tool | Scope | Mutating | Confirm | Notes |
|---|---|---|---|---|
| `search_tea` | inventory:read | no | — | Fuzzy on name/Chinese/region/vendor. Max 20. |
| `get_tea` | inventory:read | no | — | Includes last 10 ledger entries. |
| `list_low_stock` | inventory:read | no | — | Sorted by % remaining. |
| `find_customer` | customers:read | no | — | Name/company/email/phone/WhatsApp. Max 8. |
| `add_stock` | stock:write | yes | 5-min token | Logs `PURCHASE_RECEIPT`; mirrors to product_listings. |
| `remove_stock` | stock:write | yes | 5-min token | Reasons: waste/sample/personal. Auto-archive on zero. |
| `record_sale` | sales:write | yes | 5-min token | Creates + fills invoice through the same fulfillment path as the admin UI. |

**Architecturally sound:** preview/confirm pattern, activity_logs entries for every mutating call, scope check before dispatch, OAuth 2.1 for Claude Desktop. **Architecturally incomplete:** scopes aren't owner-tier gated; all four tokens get all four scopes; no batch/bulk operations.

## I.2 The coverage gap, ranked

Phone-first priorities you selected: inventory, sales/orders, customers/sourcing/settings.

### Wave 1 — high urgency (do these next)

These are the actions you hit daily and currently have to open a laptop for.

| Proposed tool | Scope | Wraps | Why now |
|---|---|---|---|
| `create_customer` | customers:write | POST /api/customers | You can find a customer; you can't onboard a new one mid-conversation. The whole record_sale flow falls back to free-text name when this is missing. |
| `update_customer` | customers:write | PUT /api/customers/:id | Adding a WhatsApp number after first sale shouldn't require a desktop. |
| `update_tea_pricing` | catalog:write | PUT /api/products/:id/commercial | Adjust retail or cost on the fly. Highest-frequency catalog edit. |
| `update_invoice` | sales:write | PUT /api/invoices/:id | Fix the customer name or notes on a just-rung sale. |
| `void_invoice` | sales:write | POST /api/rpc/void-invoice | Refund undo. Today's only voice option is "ask Claude to record_sale with negative" — that's wrong and we shouldn't let it. |
| `set_low_stock_threshold` | stock:write | PUT /api/products/:id/stock | Tune reorder triggers without opening InventoryView. |

**Confirm-token pattern for all six.** Preview must show old → new with explicit margin/balance impact where money is involved.

| Proposed tool | Scope | Wraps |
|---|---|---|

`create_product` is intentionally last. Product creation by voice is high-risk (typos in name, wrong type, no image) — it needs a stronger confirm UX, possibly with a "draft" status that requires a desktop visit to publish.

### Explicitly out of scope for MCP

Content, events, collections, magazine, wholesale orders, contributors. Reason: these are deliberative editorial actions where the friction of opening the admin is *correct*. Voice for these would invite garbage. Audit doc-level only — not a tool.

## I.3 Scope tiering — required before Wave 2

**Problem:** Today every minted MCP token gets all four scopes. The moment we add `admin:write` and `sourcing:write`, an unscoped token equals a full admin. That's wrong.

**Fix:** Two changes in `worker/src/mcp.ts` + `MCPTokensView.tsx`.

1. **Mint-time scope selection.** Checkboxes in MintForm. Default to `inventory:read + stock:write + sales:write` (today's "operator" preset). `customers:write`, `admin:write`, `sourcing:write` require explicit grant.
2. **Owner-tier gate on admin:write.** Server-side check at `dispatchTool()` — admin scopes can only be granted to tokens minted by `platform_owner` or `account_owner`. Staff cannot mint admin-scoped tokens even with members bundle.

Both are small (<200 LoC). Block Wave 2 on them.

## I.4 Why MCP-first works for this site

Three reasons specific to Teajia:

1. **WhatsApp checkout is already an MCP-shaped conversation.** Every sale is a chat. Recording it via voice/agent isn't a paradigm shift — it's removing the laptop from a flow that's already verbal.
2. **Adrian is the curator.** The 139 products are deliberate. Once the catalog is set, daily ops are stock + sales + customers — all already in scope for MCP. Editorial (magazine, events) stays desktop.
3. **Multi-store rollout needs remote control.** As operators in Australia spin up, Adrian needs to debug their inventory from Bali without remoting into their browser. MCP from a phone is the only practical path.

# Part II — Action-Flow Audit

Every action a user can take, ranked by friction. "Action" = anything that mutates state or navigates the user. Read-only views are out of scope except where the read itself is broken.

Format: **action — current flow — friction — fix**. Frictions tagged H/M/L.

## II.A Inventory & products (admin)

### A1. Add product
- **Current:** InventoryView → `+ Add` → AddProductModal → 8–12 fields (name, type, origin, vendor, price, stock, image) → save.
- **Friction (M):** Image upload + crop is a separate modal-on-modal. On mobile the stack reaches three levels and the back gesture closes the wrong layer.
- **Fix:** (1) Make image optional at create — products without images already render with a default tile. Push image to a follow-up "polish" step. (2) On mobile, replace the inner crop modal with full-screen takeover, not stacked.

### A2. Edit product field (inline)
- **Current:** Click cell → ghost input → blur saves. `api.products.updateByDomain` splits across four endpoints (catalog/stock/commercial/publication) based on field.
- **Friction (L):** Blur-save is invisible feedback. On mobile, the soft keyboard's "Done" button blurs and saves — feels right. On desktop, tab-out also saves but the user doesn't always know it did.
- **Fix:** Add a 400ms "saved" pill that fades on the cell after a successful blur-save. One line of state, no flow change.

### A3. Edit product (panel)
- **Current:** ProductEditPanel slides in from right. Tasting notes, collections, content links each live in nested modals or sub-panels.
- **Friction (M):** Three nested surfaces (panel → modal → picker) is the deepest stack in the app. On `md` widths the picker overflows.
- **Fix:** Convert TastingEditorModal and CollectionPicker to inline expandable sections within the panel. They don't need to be modals — they're not destructive.

### A4. Adjust stock (inline)
- **Current:** Inline number input in stock column, blur-saves. Logs to stock_ledger.
- **Friction (L):** Same blur-save invisibility as A2.
- **MCP:** `add_stock` / `remove_stock` exist. **This is the canonical example** of a flow that's already better by voice than by form. Promote it.

### A5. Upload/crop image
- **Current:** ImageManager modal → file picker → square crop UI → save.
- **Friction (H on mobile):** Crop UI requires precise drag; small thumbnails on phone make it tedious. iOS camera roll → crop is 4 taps.
- **Fix:** Two paths. (1) **No-crop default:** accept a 1:1 source as-is, only show crop if aspect ratio is off. (2) For non-square sources, auto-center-crop with one "adjust" button — eliminates the crop step for 80% of photos.

### A6. Mark featured / Toggle visibility
- **Current:** Star and eye icons in row. One tap, no confirm.
- **Friction (L):** Tap target on phone is ~24px. CLAUDE.md requires 44×44 minimum (`tap-target` class).
- **Fix:** Audit InventoryView row icons for `tap-target`. One-line each.

### A7. Bulk actions (visibility, export, share to network, quick invoice)
- **Current:** Long-press or checkbox column → toolbar appears → action menu.
- **Friction (M on mobile):** Multi-step selection on touch is slow; toolbar overlaps bottom nav.
- **Fix:** Two-finger drag-to-select is overkill; instead, add a sticky "Done" button that surfaces when ≥1 item is selected, and pin the bulk toolbar to the bottom-nav area (not the top) on mobile.

### A8. CSV import / export
- **Current:** Hidden in Options menu → modal with file picker + column-mapping UI.
- **Friction (M):** Discoverability — mapping UI is a desktop pattern; mobile cramped.
- **Fix:** Don't fix. CSV is a desktop tool by nature. Add a one-line "Desktop only — open on a computer" hint when the modal is opened below `md`.

### A9. AI wisdom / image enhancement
- **Current:** AI icon per row → confirmation → generates description / enhances image.
- **Friction (L):** Confirmation modal is good — these are credit-consuming.
- **MCP candidate (Wave 3):** `generate_wisdom(product_id, style)` — voice-driven content drafts.

### A10. Stock ledger view
- **Current:** Click stock detail → StockLedgerPanel shows last 10 transactions.
- **Friction (L):** None.
- **MCP:** Read-only; covered by `get_tea` (returns last 10 ledger entries).

### A11. Approve/discard pending edits

# Part III — Cross-cutting infra & risk

Source: `src/lib/store.ts`, `src/lib/api.ts`, `src/App.tsx`, `src/admin/AdminApp.tsx`, prior audit docs.

## III.1 HIGH severity

### Bundle enforcement is client-side
31 client-side `selectHasBundle()` gates. **No matching `requireBundle()` middleware on most RPC handlers** (per `STATE_OF_THE_SITE.md #2`). A forged or XSS-tampered JWT, or a curl call from a logged-in user with no bundles, can hit mutating endpoints. **Block before MCP Wave 2.**

**Fix sketch:** wrapper in `worker/src/index.ts`:
```ts
const requireBundle = (ctx, bundle) => {
  if (!ctx.bundles?.includes(bundle)) throw new Response('forbidden', { status: 403 })
}
```
Apply at top of every mutating route. ~2 days of mechanical work. Add a lint check that every `/api/*` mutating handler calls `requireBundle()` or `requirePlatformRole()`.

### Account isolation is code-enforced, not DB-enforced
D1 has no row-level security. 92 handlers × multiple table joins = thousands of places to forget `WHERE account_id = ?`. Per audit, this was done correctly today, but it's structurally fragile.

**Mitigation now:** lint check on `*.ts` files in `worker/src/` — every `SELECT` / `UPDATE` / `DELETE` against a scoped table must include `account_id` in the WHERE. Imperfect but catches drift.

**Mitigation later:** consider Cloudflare D1 + Drizzle ORM with row-level helpers, or migrate scoped tables to Postgres with RLS.

### Bundle grant changes not logged
Per `STATE_OF_THE_SITE.md #3`. Account owner promotes staff to manager → bundles update in `account_members` → no entry in `platform_audit_log`. Privilege escalation has no audit trail.

**Fix:** add audit-log insert to `PUT /api/accounts/:id/members/:userId/bundles`. 30 min.

## III.2 MEDIUM severity

### Account switch wipes draft product / cart / journal
`store.ts` lines 506–511. Switching accounts is the most common power-user flow on multi-store; losing a half-drafted product is the #1 reported friction in `OPERATIONAL_NOTES.md`-style chats.

**Fix:** scope `draftProduct` to `draftProductByAccountId: Record<string, DraftProduct>`. Keep all drafts; restore on switch. ~1 hour.

### Suspended account doesn't block writes
Per `MULTI_STORE_PLAN.md #250`. Status='suspended' is a flag with no middleware enforcement.

**Fix:** add `requireActiveAccount()` middleware check on all `/api/admin/*` mutating routes. 1 hour.

### Token refresh doesn't retry original request
`api.ts` lines 231–285. 401 triggers refresh in background; client must retry manually. User-visible 401 toast then "it worked the second time."

**Fix:** intercept 401 in `request()`, await refresh, retry once with new token, only surface error if retry also 401s. ~2 hours.

### `X-Teajia-Account` header injection is advisory
Pure convention. 6 places in the codebase set headers manually instead of calling `authHeaders()`. Race: if Zustand hasn't hydrated, header is silently absent (try/catch line 137).

**Fix:** centralize via a single `apiFetch()` wrapper that injects unconditionally from JWT claims (always available post-login) instead of Zustand state. Refactor those 6 places. ~3 hours.

### 30s fixed timeout, no backoff
`api.ts` line 69. Cold-start Workers can take 10s; rural 3G + cold start = timeout. No retry.

**Fix:** exponential backoff for transient network failures (not 4xx). Cap at 3 retries. ~2 hours.

## III.3 LOW severity

### Theme toggle hidden behind long-press
No discoverability. Tracked in `STATE_OF_THE_SITE.md #34`. Surface in AccountSettingsPage as one more toggle.

### Account switcher mobile UX
Sidebar-only on desktop; on mobile it's 3 taps deep in AccountPanel. For multi-store operators, this is daily-pain.

**Fix:** add a compact account chip to the top of AccountPanel when memberships > 1. 1 hour.

### Operating-as banner not in public routes
Adrian testing public shop as another account has no visual indication. Minor.

### Sidebar collapsed state not per-account
Persists globally; collapsed state from Bali carries to Australia. Minor.

### 13 legacy `role === 'owner'` checks
Should be `selectIsOwnerTier()`. Tracked.

# Part V — How to run the audit forward

Three habits to embed:

1. **MCP tool = first-class feature**, not afterthought. When you add a mutating endpoint, the question is "is there a phone use case?" Default yes for inventory/sales/customers; default no for content/events. A mutating endpoint with a phone use case ships its MCP tool *in the same PR*, not later.

2. **Every form is a flow document.** When you touch a form, screenshot the action sequence (entry, fields, validation, success). Compare to action-flow tables in this doc. If a step is added, the doc is the place to argue why.

3. **`requireBundle()` is non-optional.** Add the worker lint rule. The day a mutating route lands without `requireBundle()` is the day the whole permission model regresses to client-side trust. The lint catches it pre-merge.
