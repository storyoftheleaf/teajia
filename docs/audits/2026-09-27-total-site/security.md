# Worker security and tenant boundary audit — 2026-09-27

Source baseline: `2a096303`. This is an audit of the Worker REST router, public reads, MCP authentication and scopes, OAuth consent, and confirmation tickets. It does not include production requests, secrets, migrations, or code changes. Severity is based on impact if the relevant state exists; local probes establish behavior, not the current production rows.

## Confirmed findings

| ID | Severity / confidence | Impact and source trace | Smallest remedy / size |
| --- | --- | --- | --- |
| **SEC-01 — Closed stores still serve public products and events** | **P1 / high** | The profile endpoint requires `public_enabled=1` and `status='active'` ([`index.ts:20098`](../../../worker/src/index.ts)), but `/api/s/:slug/products` and `/api/s/:slug/events` use [`getAccountIdBySlug`](../../../worker/src/index.ts) at lines 20186 and 20194; that helper's query at line 591 checks only the slug. Product and event queries then serve matching rows. A store made private or suspended can still expose its catalog and event schedule through known URLs. Local no-auth D1 probe: private and suspended profiles both returned 404, while both child routes returned 200 with seeded content. | Resolve public store slugs through the existing `getPublicAccountIdBySlug` helper and add a closure regression test. **S** |
| **SEC-02 — Private events are discoverable and reveal their address** | **P1 / high** | `/api/events` selects active platform events without `public_visibility`, `network_discovery`, or active/public account checks ([`index.ts:10814`](../../../worker/src/index.ts)); `/api/s/:slug/events` likewise filters only event status and account ID (line 20217). `/api/events/:slug/public` reads any active event and includes `address_text`, `venue_guide`, and related details (lines 10674–10686). RSVP creation uses the same status-only condition (line 10854). Local no-auth D1 probe with `public_visibility='private'` and `network_discovery=0`: both lists returned the event, and the detail route returned its seeded private address. | Apply a shared event visibility predicate appropriate to discovery, direct public detail, and RSVP; gate the host account too. Add tests for private, unlisted, closed-store, and suspended-store cases. **M** |
| **SEC-03 — Shop collections disclose hidden products and closed stores** | **P1 / high** | The public `/api/collections/shop` query checks publication and collection status but does not join `accounts` or check `public_enabled`/account status ([`index.ts:23373`](../../../worker/src/index.ts)); its item query only checks `p.status='Active'`, omitting `p.is_public` and `p.shown_in_shop` (line 23424). The public link route `/api/public/c/:slug` has the same product omission and no host-account gate (lines 23750–23793). Local no-auth D1 probe seeded a private store, a hidden product (`is_public=0`, `shown_in_shop=0`), and an active shop publication: both routes returned the product. Shop publication is an explicit action, but these read paths ignore subsequent product and store privacy changes. | Filter public shop publications by open accounts and public, shown products. Clarify whether private recipient links may intentionally show hidden products; if so, enforce that policy separately from shop discovery. **M** |
| **SEC-04 — Incident intake trusts an unverified tenant header** | **P2 / high** | `/api/incidents` verifies only the JWT with `requireAuth`, then writes `X-Teajia-Account` or the token's active account directly into the global incident ledger ([`index.ts:26233`](../../../worker/src/index.ts)); [`upsertIncident`](../../../worker/src/incidents.ts) uses that value and merges by global signature. A signed-in user can attribute a report to an account they do not belong to and can affect a matching global incident's severity, count, and resolved status. Local D1 probe: user A, a member only of account A, posted with header account B; response was 201 and the ledger stored `account_id=account-b`. This is monitoring integrity, not an observed data read across tenants. | Derive account ID through the membership gate, or accept `null` for a global client incident when no account is authorized. Consider including account in the dedupe key. **S** |

## Concern to validate before scheduling a fix

**SEC-05 — OAuth scope fallback can mint unusable tokens (P3 / medium).** [`sanitizeScopesForTier`](../../../worker/src/mcp.ts) at lines 7223–7230 falls back to `DEFAULT_MCP_SCOPES` when a consent selection is absent or fully filtered. That default includes `stock:write` and `sales:write` (line 321). A viewer, or a staff member without both matching bundles, can receive a newly minted token whose scopes fail the live authority check at lines 459–462, so `/mcp` rejects the token immediately. This does not grant extra access: the live check fails closed. A focused OAuth consent/token test is needed to establish the user-visible path. The smallest fix is to intersect default and requested scopes with the approver's *current bundle authority* before minting. **S–M**

## Coverage and checks

- REST auth: traced JWT signature/session-version validation, live platform role and membership resolution, bundle and owner gates, and tenant filtering in product, customer, invoice, analytics, account, and incident families. Product/customer/invoice spot checks bind the resolved account ID. Public checkout inquiry uses `getPublicAccountIdBySlug`, so it already demonstrates the intended open-store gate.
- MCP: traced hashed token lookup, expiry/revocation, active account, live membership/bundle recheck, scope checks before built-in and module dispatch, owner-tier checks, and single-use D1 confirmation tickets bound to token/account/kind. No confirmed MCP cross-tenant authorization bypass found in the paths reviewed. Public MCP uses a four-tool allowlist and account public gate. This was a targeted source review, not a proof for every tool's SQL statement.
- Public reads: reviewed store catalog/events, event discovery/detail/RSVP, collection discovery/link, article/contributor projections, and media dispatch. The media route blocks `curate/` and `private-recordings/` keys; pending contributor draft images live under `people/.../drafts/` and have unguessable keys, so no confirmed enumeration path was found. Treat direct draft URL sharing as a separate product policy question.
- Local probes used an in-memory copy of `worker/schema.sql` and the bundled Worker; no production calls were made. Scripts, exact rerun commands, and captured output are in [security probe evidence](evidence/security-probes.md). The probes reproduced SEC-01 through SEC-04. Focused existing tests passed: `mcp-live-authorization`, `inquiry-security`, `incidents` (55 tests total), and `event-contract-routes` (81 tests). Those tests do not assert the newly found boundaries. A first test invocation omitted the repository's worktree exclusion and picked up archived checkout tests; the clean focused rerun above used the standard exclusions. No source code or tests were changed.

Known debt: `docs/ARCHITECTURE.md` still lists missing bundle/ownership audit events and a suspended-account write concern around older line references. Current `getActiveAccount` blocks suspended accounts at lines 670–750, so that old note is not counted here without a fresh path-specific proof. Existing SHA-256 password storage is a known design concern, not newly established by this audit.
