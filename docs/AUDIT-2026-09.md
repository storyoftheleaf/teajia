# Prime-time audit, 2026-09-09

Run overnight 2026-09-08/09 as one workflow: one inventory agent, ten review lanes tiered by model (Haiku inventory and ops, Sonnet screens, jobs, feel, tests, performance and code, Opus security and money), and an Opus verifier for every batch of findings. 25 agents, 58 minutes, 5.3M tokens. Every browser and API probe ran against the local sandbox, never the live shop. Plan: [todo/plans/prime-time-audit.md](../todo/plans/prime-time-audit.md).

56 findings filed, 46 confirmed by a second agent that reproduced each one, 9 rejected, 1 duplicate. Only confirmed findings appear below. Raw findings with reproduction steps and evidence are in the session scratchpad and in the workflow journal; the ten that matter are filed in `TODO.md` under "Prime-time audit".

## Found before the audit started

The live site had not deployed for two days. Two JSX comments placed between attributes in `AddProductModal.tsx` broke `tsc`, `vite build` and every Cloudflare Pages build since 2026-09-06 (six production deploys failed in a row), while the Playwright lane stayed green because nothing it loads imports the modal. Fixed and shipped as `2f1b7ea3`; teajia.com now serves the current build (bundle hash on the live site matched the new deployment). The 19 commits that had been stuck, including the Curate import fix and the freight rules, are live.

## The ten that matter, ranked

Each is one root cause. Where several lanes found the same cause through different symptoms, they are merged here and the finding ids are listed.

1. **P0. New teas ship free and carry the old markup, through five of six doors.** `worker/schema.sql` says `shipping_rate_per_kg REAL DEFAULT NULL` and `markup_multiplier` follows the shop; the live table, built from migration `0000`, still says `DEFAULT 0` and `DEFAULT 2.5`, because every fix since (0007, 0010, 0013, 0016) was an UPDATE over existing rows and SQLite cannot change a default without rebuilding the table. Only the Add Product form names the column. The bulk create, the receipt proposal, the cellar placement, the inbound import and `create_tea` all omit it and land 0, which `shippingRate.ts` reads as "Adrian said free". Measured shortfall on a probe tea: 6.9 percent of retail. The schema-defaults guard passes because it checks that a reason is written down, not that the database agrees. (JOBO-1, MONEY-1, FEEL-1, MONEY-7)

2. **P0. No gate on main runs the type check.** `deploy-frontend.yml` is `workflow_dispatch` only. `playwright.yml` starts Vite (esbuild, not tsc) and runs two spec files. No git hooks. So a syntax error unreachable from those two specs lands green, which is exactly what happened on 2026-09-06. Also unrun by any workflow: 46 browser specs, `test:china-scan`, `test:recovery`, `test:platform-hardening`. (TEST-2, TEST-1)

3. **P1. A blank cost becomes zero at four client doors.** CSV import, xlsx intake, sample graduation and the Tea Compass each convert a missing cost to 0 before the request leaves the browser, so `createMissingCost` sees a well-formed zero and the tea prices at $0.00. Reproduced end to end: a row with a blank price and currency HKD inserted with `cost_amount: 0`. The guard test for the agent door matches source text; deleting the `throw` leaves all 17 tests green. (MONEY-4, JOBO2-1, MONEY-12)

4. **P1. 21 live teas carry a currency label the admin cannot resolve.** The rates table keys yuan as `Yuan`. The worker canonicalises aliases; the admin does eight exact `===` lookups with `|| 1` on a miss, so 17 teas labelled `CNY` and 4 labelled `YUAN` display, in the Ship $/kg column, the dashboard and the invoice and purchase-order PDFs, as if their cost were dollars. `update_tea_pricing` uppercases instead of canonicalising, so it keeps creating them. The shelf price is right because the worker converts; every admin readout of those teas is wrong. (JOBO-2, MONEY-5, MONEY-10)

5. **P1. Currency provenance is stamped on two of eight write paths, so the per-vendor backlog tool would overwrite teas that stated their currency.** `stampCostCurrencySource` is called by single create and update only. Bulk create, `create_tea` and both listing mirrors leave `cost_currency_source` NULL, so a tea imported with a correctly stated HKD cost appears in `list_unstated_costs` and `set_cost_currency` would rewrite it to Yuan. **Do not run the vendor backlog decided on 2026-09-07 until this is fixed.** (MONEY-6, JOBO2-2)

6. **P1. The shop grid price omits the handling fee the ladder charges.** `TeaLedger.tsx` multiplies price per gram by weight; the product page ladder, the cart and the order total go through `quoteGrams()` and add a flat $2. Mahei Gushu Red reads $25 per 100 g on the grid and $27 two taps later. Every open-weight tea. (JOBC-1)

7. **P1. Two public write endpoints have no brake.** `POST /api/inquiries` (the checkout path, landing in Adrian's inbox) and `POST /api/newsletter/subscribe` have no rate limit and, on the consult branch, no length cap: 25 of 25 anonymous posts from one IP returned 201, a 2 MB message was stored, and the admin inbox response grew to 2.6 MB. The other limiters silently allow everything when their binding is absent. (SEC-1, SEC-2, SEC-5)

8. **P1. The wholesale catalogue quotes cost times markup as a per-gram price.** `handleNetworkCatalog` multiplies `curator_cost_amount` by the markup without dividing by `quantity_purchased`, so a 1,200 CNY, 2,000 g cake is quoted at 3,600 per gram instead of 1.80. 89 of 92 reachable listings affected. The draft order takes its unit price from this figure. (MONEY-3)

9. **P2. Draft articles are public at their URL.** `ReadIndex.tsx` is the only publish gate; the 14 article page components have unconditional routes. An anonymous visitor with empty storage read the full 10,000-character Rock Remembers interview. (JOBC-2)

10. **P2. Two boundary breaches.** `LearnCurriculum.tsx` renders a "3 day streak" computed as watched stories divided by two, against the DO-NOT-BUILD list, and the number is invented. `create_tea` defaults `type` to `Tea` and documents `Pu-erh`, neither of which is a tea type, so every tea the agent creates with the default is refused at invoice time. (OPS-3, MONEY-8)

## Rejected by the verifier

Nine findings did not survive reproduction and are not in this report: a 27k-line file with no defect named, a contact modal that cannot be reached, a media viewer that is not mounted, a TODO band claim with false evidence, a bulk-create NULL-stripping claim whose money consequence did not occur, an unparseable-freight claim blocked by the input type, a stuck tasting-note toast contradicted by the local-first save, a homepage-has-no-shop-path claim disproved in the DOM, and a "no photos" finding whose data half is true (359 of 360 products have no image) but whose UI half was wrong.

## What the audit did not reach

- Dark mode was spot-checked in code, not walked across all 156 route states.
- CSV and xlsx upload were traced and reproduced at the API, not clicked through the modal. Curate photo capture was not attempted.
- Sign-up with a code and event RSVP cannot complete in the sandbox (no code delivery, no seeded events).
- Fast-3G cold-load timing was not measured; static bundle evidence stands in.
- The product edit panel and the invoice modal were graded from source, because the sandbox API died twice under concurrent lanes (a blocked DNS lookup to wrangler's tail host, not a payload).
- Nothing in `docs/LAUNCH_VALIDATION.md` was ticked. The audit can now close none of section A by itself; items that need a real inbox, a real operator or a mainland network remain Adrian's.

## How it ran, for next time

Ten lanes against one `wrangler dev` killed it twice; next run gives the browser lanes their own API port or serialises them. Lanes left probe rows in the sandbox database (inquiries, newsletter rows, AUDIT-prefixed teas); `npm run sandbox:refresh` clears them. Verification cost roughly a third of the tokens and rejected one finding in six, which is the third that made the page trustworthy.
