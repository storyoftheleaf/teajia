### A10-1: An order voided while HOST_CREDIT is closed keeps the host's credit, and it is still there when the switch opens again
- Severity: S1 (wrong money)
- Where: worker/src/hostCreditLedger.ts:144 (`if (!hostCreditOpen(env)) return { ...NOTHING };` runs before the Void branch at :155)
- Switches: HOST_CREDIT opened, credit earned on a filled and paid order, HOST_CREDIT closed, the order voided, HOST_CREDIT opened again
- See it: `NODE_OPTIONS=--experimental-sqlite node_modules/.bin/vitest run worker/tests/review-open-then-close.test.ts -t "A10-1"`
- Evidence: "A10-1, as it stands: the void settled while closed leaves the earned row unreversed" passes (entries stay `['pending', 'earned']`, `/api/me/tea-credit` reopened shows a balance above zero); "A10-1: an order voided while the switch is closed takes its credit back" is `it.fails` and fails as expected. Nothing settles a Void invoice again, so no later action repairs it.
- Smallest fix: let the reversal run while closed (move the switch check below the Void and self-purchase branches, so closed means "earns nothing new" rather than "does nothing"), or, on the first settle after opening, reverse every earned row whose invoice is Void.
- Question for Adrian: no. (The code comment states "closed does nothing at all"; changing that contract is listed under Conflicts for Opus.)
