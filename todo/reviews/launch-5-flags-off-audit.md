# Launch 5 flags-off audit

Read-only review by GPT-6.2 Astra (Codex), 2026-11-27. Checkout: the launch-5 side of PR 560 (95708e1e) compared with main just before that merge (13143c89). build/launch-5 itself was already merged and deleted. Line numbers refer to 95708e1e.

**The eleven flags do not preserve pre-merge behavior.** The largest differences that survived PR 560 affect session discovery, reservations and waiting lists, Guest Book attribution, and which photographs and tasting excerpts remain public. I reproduced one directly: with the flags off, `/api/events` listed a public shop session on pre-merge main and omitted the same session on this checkout.

There is an important revision distinction. The requested checkout, `95708e1e`, is the second parent of merge commit `7b68d84a9`. Its first parent is the specified main revision, `13143c89`. The merge restored several things missing from the checkout. I’ve identified those separately so a checkout finding isn’t mistaken for a production regression. All line numbers below refer to `95708e1e`.

## MCP and switches outside the eleven

- **At the repository defaults, the MCP tool list matched.** The same synthetic owner token received 88 tools from each revision, with identical serialized definitions. `/mcp/public` uses its separate existing list. Direct authenticated calls do differ: the five closed Launch 3 guest/host actions, the two stop/restore actions and the three circle actions can answer `not_available` where main answered `Unknown tool`. The seven closed Launch 4 tools retain the unknown-tool answer. **Low impact, but distinguishable.** `worker/src/mcp.ts:7262`, `7338`, `7349`, `8587`, `worker/src/mcpTools/launch3.ts:145`, `worker/src/mcpTools/launch4.ts:154`, `worker/src/mcpTools/circles.ts:102`.
- **If the older `FEW_HOSTS_OPEN` switch is on, the owner gets two working tools.** With the eleven named flags still off, the same token got 90 tools: `stop_host` and `let_host_again` were added. The platform-owner HTTP action also works, although the Manage controls require `ANYONE_HOSTS_OPEN`. Stopped status can appear in owner/host answers and prevent new tables, approvals, claims and invitations. **Material.** `worker/src/mcpTools/launch3.ts:164`, `worker/src/index.ts:17468`, `17515`, `19575`, `20042`, `20190`, `23733`, `src/admin/views/PlatformAdminView.tsx:216`.
- **Reachable personal tables change under Launch 2.** An unapproved personal account’s stored link door is treated as by-request where the account remains reachable. A listed personal row omits its internal event ID. The host roster gains `offer_until` and `offer_lapsed`, removes phone numbers for departed or denied guests, and shows offer timing and different available actions. A host’s refusal through MCP now checks for freed seats. **Material to hosts and guests.** `worker/src/hostApproval.ts:179`, `worker/src/index.ts:12568`, `12877`, `worker/src/hostTableGuests.ts:133`, `141`, `src/components/host/HostTableGuests.tsx:77`, `worker/src/mcpTools/fewHosts.ts:324`.
- **Two independent switches also matter.** `HOME_BAR_OPEN` and `TABLE_CARD_OPEN` both default off. Enabling the former changes Home, navigation, keyboard destinations and shelf headings. Its houses link goes to `/tea-houses/visit`, which is unregistered while `TEA_HOUSES_OPEN` is off. Enabling the latter exposes the printable card and adds year and origin fields to the public tea menu. **Material under override**, absent at the defaults. `src/lib/homeBar.ts:17`, `src/components/navSections.ts:62`, `src/pages/teaHouses/teaHouseRoutes.tsx:25`, `src/lib/tableCard.ts:10`, `src/admin/AdminApp.tsx:586`, `worker/src/index.ts:15086`.
